## 📄 index.html — 구조

읽는 순서: `<head>` → 헤더/네비 → main 5개 섹션 → footer → 스크롤탑 버튼

| 위치 | 무엇 | 왜 |
| --- | --- | --- |
| `<html lang="ko" data-theme="light">` | 언어 + 테마 상태 | 낭독기 언어 지정 / CSS `[data-theme="dark"]`의 짝 |
| `<meta name="viewport">` | 뷰포트 설정 | 없으면 모바일이 980px로 축소 렌더링되어 반응형이 죽음 |
| `<script defer>` ×2 | config → main 순서 | 파싱 후 실행 보장 + 순서 보장 |
| `.skip-link` | 본문 바로가기 | 키보드 사용자가 메뉴를 건너뛰게 함 (Tab 누르면 나타남) |
| `header > nav` | 로고 / 메뉴 / 버튼 | Flexbox 한 줄 배치 |
| `#nav-menu` | 메뉴 `ul` | 모바일에서 숨겨졌다가 `.nav__menu--open`으로 열림 |
| `#nav-toggle` | 햄버거 | `aria-expanded`로 열림 상태를 보조기기에 알림 |
| `#hero` | 인사 + 타이핑 + CTA | `#typing` 안을 JS가 채움 |
| `#about` | `figure`+`img`+`dl` | 사진/설명 쌍은 `figure`, 항목:값은 `dl/dt/dd` |
| `#skills > ul#skill-list` | 빈 `ul` | JS가 `SKILLS` 배열로 채움 |
| `#projects` | `#filters` / `#projects-status` / `#projects-grid` | **상태 표시 영역과 카드 영역을 분리**한 것이 핵심 |
| `#contact > form` | `novalidate` | 브라우저 기본 검증을 끄고 직접 구현 |
| 각 입력 | `label[for]` ↔ `input[id]`, `aria-describedby` | 라벨-입력 연결, 에러 메시지 연결 |
| `footer` | 저작권 + 소셜 | 연도는 JS가 `new Date().getFullYear()`로 채움 |

> 💡 **설명 포인트**: "왜 상태 영역(`#projects-status`)과 카드 영역(`#projects-grid`)을 나눴나요?"
> → 로딩/에러/빈 상태와 카드 목록이 서로 다른 수명을 갖기 때문입니다. 나눠 두면
> 상태 박스만 비우거나 카드만 다시 그리는 게 쉬워집니다.

## 🎨 css/style.css — 표현

15개 구역으로 나뉘어 있고, 각 구역 위에 주석 제목이 있습니다.

| 구역 | 내용 | 시험에 나올 포인트 |
| --- | --- | --- |
| 1 | `:root` 디자인 토큰 | 색·간격·폰트·그림자를 이름으로 정의 |
| 2 | `[data-theme="dark"]` | **같은 변수명에 다른 값만** 재정의 → 규칙 재작성 불필요 |
| 3 | 리셋/기본 | `box-sizing: border-box`, `:focus-visible` 유지 |
| 4 | 헤더/네비 | **Flexbox** + `justify-content: space-between` |
| 5 | 버튼 | hover 시 `translateY(-2px)` + 그림자 |
| 6 | 섹션 공통 | `scroll-margin-top`으로 고정 헤더 보정 |
| 7 | Hero | `clamp(2rem, 8vw, 3.25rem)`로 글자 크기 자동 조절 |
| 8 | About | 모바일 1열 → 768px 이상 `260px 1fr` 2열 **Grid** |
| 9 | Skills | `repeat(auto-fit, minmax(220px, 1fr))` |
| 10 | Projects | 카드 **Grid** + 상태 박스 + 스피너/스켈레톤 |
| 11 | Form | `.form__error`에 `min-height`를 준 이유 = 메시지가 떠도 레이아웃이 흔들리지 않게 |
| 12 | Footer / 스크롤탑 | `position: fixed` + 표시 클래스 |
| 13 | `.js .reveal` | JS가 살아 있을 때만 숨김 (JS 꺼지면 그냥 보임) |
| 14 | 미디어 쿼리 | 768 / 1024, **min-width 만 사용 = 모바일 퍼스트** |
| 15 | `[data-level]` | 인라인 스타일 금지 규칙을 지키려고 게이지 너비를 CSS가 결정 |

### 꼭 기억할 3줄
```css
:root { --color-bg: #f7f8fb; }                 /* 라이트 값 */
[data-theme="dark"] { --color-bg: #0e1117; }   /* 다크 값만 교체 */
body { background: var(--color-bg); }          /* 규칙은 한 벌 */
```

## ⚙️ js/config.js — 데이터와 설정

- `PROFILE` : 이름, GitHub 아이디, 이메일, 타이핑 문구
- `SKILLS` : 스킬 카드 배열 (이 배열만 고치면 카드가 늘고 준다)
- `CONFIG` : 스크롤 기준값(60/300), 옵저버 임계값(0.2), 타이핑 속도 등 **README에 명시한 숫자들**
- `GITHUB_API_URL` : 템플릿 리터럴로 조립한 API 주소

> 💡 **설명 포인트**: "왜 파일을 나눴나요?"
> → 바뀌는 것(데이터·설정)과 바뀌지 않는 것(로직)을 분리하면, 내용을 수정할 때
> 로직을 건드리지 않아도 되고, 과제에서 요구한 "기준값"이 한눈에 보입니다.

## 🧠 js/main.js — 동작 (12개 구역)

### 0. 공통 도구
`$`, `$$` (querySelector 축약), `escapeHtml`(XSS 방어), `formatDate`(날짜 포맷)

### 1. `state` — 화면의 근거
```js
const state = {
  theme, isMenuOpen,
  projects: { status, items, error },
  activeLanguage, formErrors,
};
```
**"화면이 왜 저렇게 보이지?"의 답은 항상 여기 있습니다.**

### 2. `elements` — DOM 캐싱
자주 쓰는 요소를 한 번만 찾아 담아 둡니다. `querySelector`는 호출할 때마다 문서를 탐색하기 때문입니다.

### 3. 다크 모드
```
클릭 → setTheme() → state.theme 변경 + localStorage 저장 → renderTheme() → <html data-theme>
```
초기화는 `localStorage` → 없으면 `prefers-color-scheme` 순서. (`??` 사용)

### 4. 네비게이션
- 햄버거: `setMenuOpen(!state.isMenuOpen)` → `renderMenu()`가 클래스와 `aria-expanded`를 함께 갱신
- 링크 클릭: `preventDefault()` → `scrollIntoView({behavior:'smooth'})` → `history.pushState` → 메뉴 닫기
- ESC 키, 768px 이상으로 넓어질 때 자동 닫기

### 5. 스크롤 효과
한 개의 `handleScroll()`이 세 가지를 처리합니다.
1. 헤더 배경(60px 초과) 2. 맨 위로 버튼(300px 초과) 3. 스크롤 스파이(현재 섹션 강조)
`requestAnimationFrame` + `ticking` 플래그로 과도한 호출을 막습니다.

### 6. 등장 애니메이션
`IntersectionObserver`, `threshold: 0.2`. 나타난 요소는 `unobserve`로 감시 해제.
지원하지 않는 브라우저는 전부 보이게 처리(점진적 향상).

### 7. 타이핑 효과
`charIndex`를 늘리고 줄이며 `textContent`에 `slice(0, charIndex)`를 넣습니다.
다 쓰면 `TYPING_HOLD`만큼 멈췄다가 지우고, 다음 문장으로(`% taglines.length`).

### 8. Skills 렌더링
`SKILLS.map(...).join('')` → `innerHTML` **한 번**. (`+=` 반복은 느립니다)

### 9. GitHub API ★
```
fetchProjects()
  ├ setProjectsState({status:'loading'})   → 스피너 + 스켈레톤
  ├ await fetch(url)
  ├ if (!response.ok) → 403/404/기타로 나눠 throw
  ├ await response.json()
  ├ filter(!fork) + sort(스타순)   ← 원본은 [...repos]로 복사
  ├ 성공 → setProjectsState({status:'success', items})
  └ catch → TypeError면 네트워크 메시지, 아니면 던진 메시지
```
`renderProjects()`가 `status`에 따라 **4가지 화면 중 하나**를 그립니다.
재시도/필터 버튼은 **이벤트 위임**으로 처리합니다.

### 10. 폼 검증
- `validateField(id, value)` → 에러 문자열(없으면 `''`) **반환만** 하는 순수 함수
- `renderFieldError(id)` → `state.formErrors`를 보고 메시지/테두리/`aria-invalid` 반영
- `submit` → `preventDefault()` → 전체 검증 → 첫 오류 필드에 `focus()` → 통과 시 성공 메시지 + `reset()`
- `input` 이벤트에서는 **이미 에러가 있는 필드만** 재검증 (입력 시작부터 잔소리하지 않기)

### 11. 마무리
연도 자동 표시, 푸터 GitHub 링크를 `PROFILE.githubUsername`으로 조립

### 12. `init()`
`document.documentElement.classList.add('js')` → 각 기능 초기화.
**순서 주의**: `renderSkills()`가 `initRevealAnimation()`보다 먼저여야 합니다.
스킬 카드가 만들어진 뒤에 옵저버가 그것들을 감시할 수 있기 때문입니다.

## 🔍 "한 기능을 끝까지 따라가기" 연습

동료가 "아무 기능이나 하나 골라서 처음부터 끝까지 설명해 보세요"라고 하면
**언어 필터**가 가장 짧고 완결됩니다.

1. `renderFilters()`가 `items.map(repo => repo.language).filter(Boolean)` 로 언어를 모으고
   `new Set()`으로 중복을 제거해 버튼을 그린다.
2. 사용자가 버튼을 클릭한다. 버튼은 JS가 만든 것이라 부모 `#filters`에 건 리스너가 받는다(위임).
3. `event.target.closest('.filter-btn')`으로 버튼을 특정하고 `dataset.lang`을 읽는다.
4. `state.activeLanguage`를 바꾼다. **(상태 변경)**
5. `renderProjects()`를 호출한다. **(렌더링)**
6. 렌더 함수는 `items.filter(repo => repo.language === state.activeLanguage)`로 보여줄 목록을 만들고
   `map`으로 카드를 그린다. 원본 `items`는 그대로라 All 을 누르면 즉시 복구된다.

→ 이벤트 → 상태 → 렌더링이 6단계 안에 전부 들어 있습니다.
