# 01. 동료평가 시연 대본 (약 15분)

> 평가자 앞에서 **화면을 보여주며** 말하는 순서입니다.
> 굵은 글씨는 그대로 말해도 되는 문장, 회색 인용은 행동입니다.
> 준비물: 배포 URL 을 연 브라우저 탭 1개 + VS Code 로 연 프로젝트 1개.

---

## 0. 여는 말 (30초)

> 배포된 사이트를 전체화면으로 띄운 채 시작

**"이 미션은 프레임워크 없이 순수 HTML·CSS·JavaScript로 반응형 포트폴리오를 만드는 과제였습니다.
제가 이 과제에서 가장 신경 쓴 건 화면 디자인이 아니라, **사용자 이벤트 → 상태 변경 → 화면 렌더링**
이라는 흐름을 코드에서 눈에 보이게 만드는 것이었습니다.
지금부터 화면을 먼저 보여드리고, 그 다음 코드에서 그 흐름을 짚어드리겠습니다."**

## 1. 반응형 (2분)

> 데스크톱 → 브라우저 창을 천천히 좁힘 → 모바일 크기

**"모바일 퍼스트로 작성했습니다. 기본 CSS가 모바일이고, `min-width: 768px`, `1024px` 두 개의
미디어 쿼리로 넓은 화면을 덧칠하는 방식입니다.
창을 좁히면 768px 아래에서 가로 메뉴가 사라지고 햄버거 버튼이 나타납니다."**

> 햄버거 버튼 클릭 → 메뉴 열림 → 메뉴 항목 클릭 → 메뉴 닫히며 해당 섹션으로 이동

**"햄버거는 `classList.toggle`로 클래스 하나만 켜고 끄고, 실제로 보이고 숨기는 건 CSS가 담당합니다.
JS는 '상태가 열림이다'만 알려주고, 표현은 CSS가 하는 역할 분리입니다."**

**"About 은 사진과 글이 2열로 배치되는 부분이라 Grid 를 썼고,
네비게이션은 로고와 메뉴를 한 줄에 양 끝으로 배치하는 1차원 배치라 Flexbox 를 썼습니다."**

## 2. 다크 모드 + 상태 유지 (2분)

> 다크 모드 토글 클릭

**"토글을 누르면 `<html>` 태그의 `data-theme` 속성이 light ↔ dark 로 바뀝니다.
CSS에서는 `:root`에 라이트 색 변수를, `[data-theme="dark"]`에 다크 색 변수를 정의해 뒀기 때문에
속성 하나만 바꾸면 화면 전체 색이 한 번에 바뀝니다. 색을 쓰는 규칙은 한 번만 작성했습니다."**

> 개발자도구 Elements 에서 `<html data-theme="dark">` 를 보여주면 더 좋음

> **새로고침(F5)** — 다크 모드가 유지됨을 보여준다

**"선택한 테마는 `localStorage`에 저장합니다. 페이지가 다시 열릴 때 저장된 값을 먼저 읽고,
저장된 값이 없으면 `prefers-color-scheme`으로 운영체제 설정을 따라갑니다."**

## 3. GitHub API 와 4가지 상태 (4분) ★ 가장 중요

> Projects 섹션으로 스크롤. (새로고침 직후라면 스피너가 잠깐 보임)

**"Projects는 제가 직접 적은 게 아니라 GitHub API에서 실시간으로 가져옵니다.
`fetch`와 `async/await`로 요청하고, 화면은 네 가지 상태로 나눠서 그립니다."**

**"1) 로딩 — 스피너와 카드 자리를 잡아주는 스켈레톤을 보여줍니다.
2) 성공 — 받은 배열을 `map`으로 카드 HTML로 바꿔 한 번에 그립니다.
3) 에러 — 실패 메시지와 다시 시도 버튼을 보여줍니다.
4) 빈 상태 — 저장소가 하나도 없을 때의 안내를 보여줍니다."**

> **에러 상태 시연** (둘 중 하나)
> - 방법 A: 브라우저 개발자도구 → Network 탭 → **Offline** 체크 → 새로고침
> - 방법 B: 개발자도구 Console 에 아래를 붙여넣기
>   ```js
>   setProjectsState({ status: 'error', items: [], error: '네트워크 연결을 확인해 주세요.' })
>   ```

**"에러는 `try/catch`로 잡습니다. 주의할 점은 `fetch`가 404나 403 같은 응답도 '성공'으로
넘긴다는 것입니다. 그래서 `response.ok`를 직접 확인하고, 403이면 'API 호출 한도 초과',
404면 '사용자를 찾을 수 없음'처럼 원인별로 다른 메시지를 던집니다."**

> **다시 시도 버튼 클릭** → 다시 로딩 → 성공

**"다시 시도 버튼은 에러가 났을 때 JS가 만들어내는 요소라 처음엔 존재하지 않습니다.
없는 요소에는 이벤트를 걸 수 없으니, 항상 존재하는 부모 컨테이너에 리스너를 한 번만 걸고
`event.target`으로 누가 눌렸는지 판별하는 **이벤트 위임**을 사용했습니다."**

> 언어 필터 버튼 클릭 (예: JavaScript)

**"필터는 `filter`로 원본 배열은 그대로 두고 보여줄 것만 골라 다시 렌더링합니다.
원본을 지우지 않기 때문에 All 을 누르면 바로 되돌아옵니다."**

## 4. 폼 유효성 검사 (2분)

> Contact 로 이동 → 아무것도 안 넣고 **보내기** 클릭

**"세 필드 모두 에러 메시지가 입력창 바로 아래에 뜨고, 테두리가 빨갛게 바뀝니다.
그리고 첫 번째 문제 필드로 커서가 자동으로 이동합니다."**

> 이메일에 `abc` 만 입력하고 다시 제출

**"이메일은 정규식으로 '공백 없는 문자 + @ + 문자 + . + 문자' 형식을 검사합니다.
`novalidate`로 브라우저 기본 검증을 끄고 직접 구현했는데, 메시지 문구와 표시 위치를
제가 제어하고 싶었기 때문입니다."**

> 올바르게 채우고 제출 → 성공 메시지

**"제출은 `event.preventDefault()`로 기본 동작인 새로고침을 막습니다.
막지 않으면 페이지가 리로드되면서 지금까지의 화면 상태가 전부 초기화됩니다."**

## 5. 코드에서 흐름 짚기 (3분) ★ 평가 포인트

> VS Code 로 전환, `js/main.js` 를 열고 위에서 아래로 스크롤

**"main.js는 12개 구역으로 나눠져 있습니다. 핵심은 1번 구역의 `state` 객체입니다.
화면에 보이는 모든 것의 근거가 여기 있습니다."**

```js
const state = {
  theme: 'light',
  isMenuOpen: false,
  projects: { status: 'idle', items: [], error: '' },
  activeLanguage: 'All',
  formErrors: {},
};
```

**"그리고 모든 기능이 같은 3단 구조를 갖습니다."**

| 기능 | ① 이벤트 | ② 상태 변경 | ③ 렌더링 |
| --- | --- | --- | --- |
| 다크 모드 | `themeToggle` click | `state.theme` | `renderTheme()` → `data-theme` |
| 프로젝트 | 페이지 로드 / 재시도 click | `state.projects.status` | `renderProjects()` |
| 필터 | 필터 버튼 click | `state.activeLanguage` | `renderProjects()` |
| 폼 | form submit | `state.formErrors` | `renderFieldError()` |
| 메뉴 | 햄버거 click | `state.isMenuOpen` | `renderMenu()` |

**"React의 `useState`와 리렌더링이 정확히 이 구조입니다.
React는 ③번 렌더링을 자동으로 해 주는 것이고, 여기서는 제가 직접 호출한 것뿐입니다.
그래서 이 미션이 다음 React 미션의 기반이 된다고 이해했습니다."**

## 6. 마무리 (30초)

**"정리하면, 시맨틱 태그로 의미를 드러내는 구조를 만들고, CSS 변수와 미디어 쿼리로
한 벌의 스타일이 두 테마·세 화면 크기에서 동작하게 했고,
JavaScript는 이벤트를 받아 상태를 바꾸고 그 상태로 화면을 다시 그리게 했습니다.
질문 주시면 코드 열어서 같이 보겠습니다."**
