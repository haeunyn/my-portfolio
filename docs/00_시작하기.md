1. 배포 URL 을 열어 **직접 클릭해 보며** 확인한다.
   - 햄버거 메뉴 / 다크 모드 / 새로고침 후 테마 유지 / 폼 에러 / 프로젝트 카드
2. `index.html` 의 소개 문장을 **본인 표현으로 다듬는다.** (Hero, About)
   → 학칙 제10조 ③ "해결책을 스스로 도출" 과 직결되는 부분입니다.
3. `docs/03_코드해설.md` 를 켜 놓고 **코드를 위에서 아래로 한 번 읽는다.**
4. `docs/02_예상질문과답.md` 의 질문에 **소리 내어** 답해 본다.
   막히는 질문이 있으면 그 부분 코드를 다시 읽는다.
5. 수정했으면 반영한다.
   ```bash
   git add -A && git commit -m "docs: 소개 문구 수정" && git push
   ```
   1~2분 뒤 배포 사이트에 자동 반영됩니다.

## ⚠️ 학칙과 관련해 꼭 알아야 할 것

코디세이 학칙에서 이 과제와 직접 관련된 조항입니다.

| 조항 | 내용 | 나에게 필요한 행동 |
| --- | --- | --- |
| 제10조 ③ | 교육생은 **학습 과제의 해결책을 스스로 도출**하여야 한다 | 코드를 그대로 두지 말고, 읽고 이해하고 **본인 문장·본인 값으로 고쳐** 두세요 |
| 제9조 ④ (학습 부정행위) | 타인의 코드 사용·표절 시 경고 (**GitHub 등 외부 출처 포함**) | 남의 저장소를 복사해 오지 마세요. 이 코드는 본인 과제 폴더에서 본인이 다듬는 것을 전제로 합니다 |
| 제9조 ④ | **작동하지 않는 코드에 점수 부여 금지** — 적발 시 평가자·피평가자 **양측 모두 경고** | 평가 전에 배포 URL에서 모든 기능이 실제로 도는지 반드시 확인 |
| 제9조 ② 5호 | 평가 중 **논리적 설명 요구** 가능 | "왜 이렇게 했는지"를 말할 수 있어야 통과입니다. 이 docs 폴더가 그 준비물입니다 |
| 제9조 ② 1·2호 | 대면 평가는 **교육장에서**, 피평가자·평가자 모두 참석 / 무단 취소 금지 | 평가 일정 잡으면 지키고, 못 가면 미리 연락해 재조율 |
| 제9조 ② 6호 | **평가자는 피평가자의 자리에서** 평가를 진행 | 본인 자리에서 본인 노트북으로 시연 |

> 핵심: **동료평가는 "코드가 있느냐"가 아니라 "설명할 수 있느냐"를 봅니다.**
> 설명할 수 없는 줄이 있으면 그 줄을 지우거나, 이해될 때까지 뜯어보세요.

## 🧭 이해도 자가 진단

아래 8개에 막힘없이 답할 수 있으면 평가 준비가 된 것입니다.

- [ ] `div` 대신 `section`, `header` 를 쓴 이유를 말할 수 있다
- [ ] 네비게이션은 Flexbox, 카드는 Grid 로 만든 이유를 말할 수 있다
- [ ] `querySelector` → `addEventListener` → 화면 변경으로 이어지는 흐름을 하나 짚어 설명할 수 있다
- [ ] 화살표 함수 / 구조분해 할당 / `map` / `filter` 가 코드 어디에 왜 쓰였는지 짚을 수 있다
- [ ] `async/await` 와 `try/catch` 로 로딩·성공·에러·빈 상태를 어떻게 나눴는지 말할 수 있다
- [ ] 다크 모드가 새로고침 후에도 유지되는 원리를 말할 수 있다
- [ ] 모바일 퍼스트가 무엇이고 왜 `min-width` 미디어쿼리를 쓰는지 말할 수 있다
- [ ] "이벤트 → 상태 → 렌더링" 흐름을 이 프로젝트에서 3가지 예로 들 수 있다
